# מעקב הוצאות טיול

בסיס ראשוני לאפליקציית מעקב הוצאות למטיילים. HTML/CSS/JS פשוט (ES modules), בלי build step — פותחים ומריצים.

## הרצה

פתחו את `index.html` בדפדפן, או הריצו שרת סטטי מקומי:

```bash
npx serve .
```

(אפשר גם `python -m http.server` אם אין Node.js מותקן.)

## מבנה הפרויקט

```
expense-tracker/
├── index.html            # מבנה העמוד
├── css/style.css          # עיצוב, mobile-first
├── backend/
│   ├── AppsScript.gs       # "שרת" קטן על Google Sheets, לתיעוד אוטומטי מהאייפון
│   └── serve.ps1            # שרת סטטי מקומי לבדיקות (אין Node/Python על המחשב)
└── js/
    ├── categories.js      # רשימת קטגוריות הוצאה
    ├── countries.js        # רשימת מדינות + דגלים
    ├── geo.js               # מיקום נוכחי + זיהוי מדינה (Geolocation + reverse geocoding)
    ├── currency.js          # מיפוי מדינה→מטבע + שער חליפין לשקל
    ├── storage.js            # שמירה/טעינה מ-localStorage
    ├── config.js             # כתובת ה-Apps Script (ריק = בלי סנכרון)
    ├── remote.js              # תקשורת עם ה-Apps Script
    ├── expenses.js            # לוגיקת CRUD להוצאות + סנכרון
    ├── export.js              # ייצוא הטבלה ל-.xlsx אמיתי (כותרות מודגשות, תאריכים אמיתיים) דרך ExcelJS
    └── main.js                # חיבור בין הרכיבים + רינדור
```

הטופס מינימלי בכוונה: המשתמש מזין רק **סכום, קטגוריה, פירוט (אופציונלי) והאם זו קניה קבוצתית**. תאריך, מיקום, מדינה ומטבע מזוהים אוטומטית (Geolocation בדפדפן + [bigdatacloud.net](https://www.bigdatacloud.com/) לזיהוי מדינה/עיר, [open.er-api.com](https://www.exchangerate-api.com/) לשער החליפין לשקל, מתעדכן פעם ביום ונשמר במטמון מקומי). מספר המטיילים בקבוצה (לחישוב "העלות שלך") נשמר ונשאר עד שמשנים אותו. אפשר לשנות את התאריך בעצמו (שדה קטן ב"עוד משהו?" שמוגדר מראש ל"היום") וכל שדה אחר ניתן לעריכה אחר כך מתוך מסך פרטי ההוצאה — כולל סימון "לא לכלול בסה\"כ" להוצאות שלא אמורות להיכנס לתקציב (למשל החזר כספי או קניה עבור מישהו אחר).

בתחתית טאב הסיכומים יש כרטיס "קצב הוצאות": כמה הוצאת בטיול, כמה ימים עברו מתוך סך ימי הטיול, ממוצע יומי, ותחזית לסך שיוציא הטיול אם הקצב הנוכחי יימשך. דורש הגדרה חד-פעמית של תאריך התחלה/סיום הטיול (כפתור בתוך הכרטיס). אותו רעיון קיים גם לכל מדינה בנפרד (ימים במדינה + ממוצע יומי/חודשי), במסך הפירוט שנפתח בלחיצה על מדינה.

**קיזוז עם חברים** (טאב "קיזוז"): מוסיפים שמות מטיילים, ובכל הוצאה מסומנת כ"קניה קבוצתית" בוחרים מי שילם בפועל ומי משתתף, ואיך לחלק — שווה בשווה, סכום מדויק לכל אחד, או אחוזים (עם אינדיקציה חיה אם הסכום/האחוזים לא מסתכמים לסה"כ). האפליקציה מחשבת מאזן נטו לכל אדם (כולל אווטאר צבעוני עם ראשי תיבות) על פני כל ההוצאות, ומצמצמת את זה לרשימת העברות מינימלית ("מי חייב למי"), עם כפתור "✓ סמן כסודר" לכל העברה (רושם קיזוז ידני שמנוטרל מהמאזן) וכפתור להעתקת הסכום ללוח (כדי להדביק בביט/פייבוקס/כל אפליקציית תשלום אחרת — אין אינטגרציה ישירה, כי אין API ציבורי שמאפשר למלא מראש נמען+סכום). אנשים עם מאזן מאופס עדיין מוצגים ("מאופס ₪0"). הסרת מטייל עם חוב פתוח דורשת אישור. "אני" תמיד חלק מהמשתתפים הפוטנציאליים; אפשר להוסיף חבר חדש גם ישירות מתוך בורר המשתתפים בהוספת הוצאה.

אפשר לתת שם לטיול (שדה בראש טאב "קיזוז"), וליצור **קבוצות** ולשייך אליהן מטיילים — מאזני החובות מוצגים מסודרים לפי קבוצה ו"אנשים בודדים" בנפרד. מחיקת קבוצה לא מוחקת את חבריה, רק מבטלת את השיוך.

לוחצים על שם קבוצה כדי לראות מסך עם המשתתפים שלה בלבד (עם המאזן העדכני של כל אחד) — מי שלא משויך לאף קבוצה מופיע רק ברשימות הכלליות ("מאזן לכל אחד" ו"מי חייב למי"), לא במסך הזה. ברשימת הקבוצות עצמה מוצג גם מספר המשתתפים וגם "המצב הכספי שלי בקבוצה" (בצבע, כמו בשאר מקומות באפליקציה) — מחושב מתוך גרף הקיזוז המפושט (`simplifyDebts`) ולא מסכימה נאיבית של ההוצאות, ולכן זה משקף כמה **באמת** נשאר לסגור מול אנשי הקבוצה אחרי שכל החוב ברשת קוזז, לא כמה שילמת/חייבת ישירות עבורם.

כל קבוצה כוללת כפתור **קישור הזמנה** (אייקון 🔗 בלבד — לחיצה מעתיקה ומציגה הודעת "קישור הועתק" קטנה, בלי לפתוח דיאלוג עם הטקסט הגולמי) — מעתיק קישור שמי שפותח אותו מתבקש להזין את שמו ומצטרף לקבוצה. אם מוגדר `API_URL`, ההצטרפות נרשמת בגיליון Google Sheet משותף (טאב "Groups" חדש שה-Apps Script יוצר אוטומטית) והקישור גם מעביר את כתובת ה-API למצטרף, כך שהמכשיר שלו יתחיל לדבר עם אותו גיליון בלי הגדרה ידנית. **חשוב:** הקישור מכיל את `location.href` הנוכחי — כרגע זה `localhost`, ולכן יעבוד רק על המחשב הזה. ברגע שתארחו את העמוד אונליין (ראו הערה למטה), הקישורים שנוצרים משם והלאה יעבדו לכל אחד.

**מגבלה מכוונת:** כרגע רק אדם אחד יכול להיות ה"משלם" בכל הוצאה (לא כמה משלמים על אותה הוצאה) — זה כיסה את רוב המקרים בפועל, ותומך בזה היה דורש שינוי ארכיטקטורה משמעותי.

כפתור "ייצוא טבלה" (בתחתית טאב הסיכומים) פותח בחירה בין שני פורמטים: **Excel (.xlsx)** — כותרות מודגשות ותאריכים כתאי-תאריך אמיתיים, דרך [ExcelJS](https://github.com/exceljs/exceljs) שנטען מ-CDN (צריך אינטרנט בפעם הראשונה, הדפדפן שומר במטמון אחר כך) — או **CSV** פשוט (בלי תלות ברשת), שנפתח גם באפליקציית Numbers של אפל, Google Sheets וכל תוכנת גיליונות אחרת.

הנתונים נשמרים ב-`localStorage` מקומי, ואם מגדירים `API_URL` ב-`js/config.js` — גם מסונכרנים עם Google Sheet משותף (ראו "תיעוד אוטומטי מהאייפון" למטה).

### הרצה לבדיקה מקומית

אין Node/Python מותקנים במחשב הזה, אז יש שרת סטטי מינימלי ב-PowerShell:

```bash
powershell -ExecutionPolicy Bypass -File backend/serve.ps1
```

ואז פותחים http://localhost:8765/ בדפדפן.

## תיעוד אוטומטי מהאייפון (Shortcuts)

הרעיון: אוטומציה ב-Shortcuts שקופצת כשמגיעה התראת חיוב אשראי, שואלת סכום + קטגוריה בכמה קליקים, ושולחת ברקע (בלי לפתוח Safari) ל-Google Apps Script ששומר ל-Google Sheet משותף. העמוד באתר קורא מאותו Sheet.

**שלב 1 — הקמת ה-"שרת" (חד-פעמי, בדפדפן במחשב):**
1. [script.google.com](https://script.google.com) → New project → מדביקים את כל התוכן של [backend/AppsScript.gs](expense-tracker/backend/AppsScript.gs).
2. יוצרים Google Sheet חדש, מעתיקים את ה-ID שלו מהכתובת (`.../d/`**`ID`**`/edit`), ומדביקים אותו במקום `PASTE_YOUR_GOOGLE_SHEET_ID_HERE` בקוד.
3. Deploy → New deployment → Web app. Execute as: *Me*, Who has access: *Anyone*.
4. מעתיקים את ה-URL שמתקבל (מסתיים ב-`/exec`).
5. מדביקים אותו כ-`API_URL` בקובץ [js/config.js](expense-tracker/js/config.js).

**שלב 2 — בניית האוטומציה באייפון (באפליקציית Shortcuts):**
1. Automation → New Automation → App → בוחרים את אפליקציית הבנק/ארנק שמציגה התראות חיוב → Notification received (או Wallet: "Transaction").
2. כבים "Ask Before Running" כדי שזה יקפוץ אוטומטית.
3. מוסיפים פעולת **Ask for Input** (Number) לסכום.
4. מוסיפים **Choose from Menu** עם הקטגוריות: אוכל / תחבורה / לינה / בילויים / קניות / אחר.
5. מוסיפים **Get Contents of URL**:
   - URL: ה-`/exec` URL מהשלב הקודם.
   - Method: POST
   - Request Body: JSON עם השדות: `date` (`yyyy-MM-dd`), `location`, `country` (קוד בן 2 אותיות, למשל `TH`), `category` (food/transport/lodging/activities/attractions/shopping/medical/gear/service/other), `note`, `amountLocal`, `currencyLocal` (למשל `THB`), `amountILS`, `isGroup` (true/false), `paidBy` (שם או `me`), `participants` (שמות מופרדים בפסיקים, למשל `me,ריף,עומר`), `excludeFromTotal` (true/false, אופציונלי).
6. זהו — זה רץ ברקע, בלי לפתוח דפדפן. באפליקציה לוחצים 🔄 (מופיע כש-`API_URL` מוגדר) כדי למשוך את מה שנוסף.

## הערות ידועות / להמשך פיתוח

- אין המרת מטבעות — הסכום הכולל מניח מטבע אחיד לטיול.
- אין ריבוי טיולים — כרגע כל ההוצאות ברשימה אחת.
- תמונות (קבלות) נשמרות רק מקומית בדפדפן (base64 ב-localStorage), דחוסות אוטומטית לכ-900px — לא מסונכרנות ל-Google Sheet ולא בין מכשירים. localStorage מוגבל לכמה MB, אז הרבה תמונות לאורך טיול ארוך עלולות למלא את המכסה.
- זיהוי מיקום אוטומטי דורש הרשאת Geolocation מהדפדפן, ורק עובד ב-context מאובטח (HTTPS או localhost) — לא יעבוד אם מארחים על HTTP רגיל.
- אם המשתמש דוחה את הרשאת המיקום, או שאין רשת — האפליקציה נופלת חזרה למדינה/מטבע האחרונים שזוהו בהצלחה (או ישראל/₪ כברירת מחדל), ומציגה אזהרה קטנה.
- אם כבר פרסת את ה-Apps Script לפני עדכון סכימה (למשל הוספת `excludeFromTotal`, או `groupSize`→`paidBy`/`participants`) — הגיליון הקיים שלך עדיין עם הכותרות הישנות, אז שורות חדשות ייכתבו לא מיושרות. פותרים בעדכון ידני של שורת הכותרות בגיליון, או פריסה לגיליון חדש.
- ללא `API_URL` — אין סנכרון בין מכשירים, הנתונים מקומיים לדפדפן בלבד.
- העמוד עצמו עדיין רץ רק מקומית (לא מאוחסן אונליין). זה לא חוסם את התיעוד האוטומטי מהאייפון (הוא מדבר ישירות עם ה-Apps Script), אבל כדי לפתוח את *העמוד עצמו* מהטלפון (או כדי שקישורי הזמנה לקבוצה יעבדו לאנשים אחרים) צריך לארח אותו איפשהו — למשל GitHub Pages (חינמי, דורש ריפו ב-GitHub).
- כל המסכים גוללים כשהתוכן ארוך מהמסך (`overflow-y: auto` על כל `.screen`) — זה קריטי במסכים עם הרבה שדות (למשל הוספת הוצאה קבוצתית עם כל אפשרויות הפיצול) על מסכי טלפון קטנים; בלי זה חלק מהתוכן והכפתורים הופכים לבלתי-נגישים.

## עבודה משותפת

כשמצטרפים לעבוד יחד על חלקים שונים:

1. כל אחד עובד על ענף (branch) נפרד: `git checkout -b feature/שם-הפיצ'ר`
2. מומלץ לחלק לפי מודולים/קבצים כדי למזער התנגשויות (למשל: מסך הוצאות מול מסך תקציב/טיולים).
3. מזגו הביתה (`main`) לעיתים קרובות עם Pull Requests קטנים במקום מיזוג ענק בסוף.
4. אם מוסיפים מסך/פיצ'ר חדש — עדיף כקובץ JS חדש תחת `js/` עם ייצוא ברור (`export`), כדי ש-`main.js` רק "יחבר" בין החלקים.
